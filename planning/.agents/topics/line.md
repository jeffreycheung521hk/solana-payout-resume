# line：線的須知、開場提示與交接

- 載入：被開成一條線、派子代理、寫交接，或被壓縮後續接時。
- 不載入：只讀不改的一次性問答。

## 角色

| 角色 | 做什麼 | 不做什麼 |
|---|---|---|
| 統籌 | 決定開哪幾條線、併入 main、跨線轉告、收線核對 | 不出設計卡片 |
| 線 | 出形狀卡和決策包、寫回、寫程式碼，只在自己的分支提交 | 不開新 Session、不併入 main |
| 審查線 | 唯讀檢視程式碼，只寫 `records/review/`，產出審查包 | 不改程式碼 |
| 子代理 | 通讀、跑檢查、寫測試、寫形狀已定死的機械程式碼 | 不在寫回裡加沒裁決的內容 |

本範例沒有獨立的統籌 Session：統籌由使用者兼任，負責裁決與按下 merge。

## 線的須知

開線時把這一節整段放進開場提示；線派子代理時放在提示開頭。
原因：規則只放在主題裡時，Session 一長或被壓縮，細節就會掉；子代理只拿得到線給它的那段提示。

1. 和使用者交流用台灣繁體中文。
2. 決策包一包最多 5 項、6000 字，一則訊息只出一包；較長的推演放 `records/`，聊天裡給路徑。
3. 寫回只寫使用者裁決過的項，diff 的每一塊都要對得上一個裁決；對不上的不寫，並在回執說明。
4. 新的外部相依先問使用者；新的公開名字按 `terminology.md` 的命名規則定，規則定不了才問。
5. 只有統籌併入 main。
6. 只在自己的分支提交；寫回後 rebase 到 main 再報。
7. 每次寫回前、被壓縮後，重讀 `design-collab.md`。
8. 只在有提交要併入或有跨線影響時才回報，不發只報進度的訊息。
9. 機械工作（寫回、跑檢查、照已裁決結論改程式碼）可以交給較便宜的子代理；出卡和設計推理不行。
10. 實作取捨同時滿足三個條件就自己定、寫完再報：不改公開 trait 或公開類型的形狀；不違反已確認的文件；能由協定或現有規則推出。否則出卡。
11. 程式碼以批為合併單位：批內跨幾個 Session 都留在分支上，批末才報；設計寫回和術語表更新每批一次。
12. 子代理只寫測試或形狀已定死的機械程式碼；行為已定死、量大的一塊可以交給同級模型的子代理，線逐行複查最終 diff。
13. Context 接近上限時，在段落交界寫好交接再換 Session；線不自己開新 Session，由統籌開。
14. 收到停止通知：做完手上這一步就停，不再出卡、不再派子代理；把已裁決未寫回的內容和停點寫進交接，有未報的提交就報。
15. 使用者說這條線結束：先寫完交接，再報狀態（交接位置、有沒有未報的提交或未提交的改動）。

## 開場提示清單

統籌開線時依序寫：

1. 第一句「你是「<線名>」」。
2. 範圍：負責什麼、不負責什麼。
3. 分支名。
4. 權限：能改哪些路徑、能不能提交、能不能派子代理。
5. 上面「線的須知」全文。
6. 開工先讀什麼：workspace 主題、按觸發表要載入的主題、要接的交接。
7. 第一件事做什麼。

## 交接清單

1. 已裁決、還沒寫回的項，逐條寫出內容。
2. 等使用者回覆的卡片：寫正文或檔案路徑，不能只寫選項字母。
3. 停點和下一步。
4. 分支狀態：最後的提交、有沒有未報的提交、有沒有未提交的改動。
5. 跨線要轉告的事。
6. 統籌的交接另外寫：使用者已定未做的事、各線狀態與交接位置。
