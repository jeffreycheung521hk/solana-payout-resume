# instructions：維護指令體系

- 載入：修改任何 `AGENTS.md` 或 `.agents/` 時。
- 不載入：其他任務。

## 結構

- 根目錄 `AGENTS.md` 只放三條指標：指令體系在哪裡、每個 Session 先讀 workspace 主題、其餘按觸發表載入。不寫觸發表、規則正文、原因或例外。改它之前先備份。
- 原因：根路由每個 Session 都會載入。規則寫在那裡，既增加固定讀入，又會和主題形成兩份副本。
- 觸發表只有一張，在 `planning/AGENTS.md`；每行是「任務觸發條件 → 必須載入的主題」。
- `planning/docs/AGENTS.md` 這類目錄路由只放指標，不放規則正文。
- 每條規則只有一個規範來源；路由裡不複製規則正文。
- 共享主題保持工具中立，不假定 Agent 一定有某種技能、子代理介面或瀏覽器。

## 主題的寫法

- 每個主題都有載入條件、不載入條件和規則；高影響的規則寫原因，必要時寫作用域或例外。
- 使用者明確提出的規則標「要求」，能取得原話就附上。
- 新舊規則衝突時，在舊規則的位置修訂並註明替代關係，不在末尾追加一條。
- 只有使用者明確表達過的偏好寫成已確認；Agent 自己的推測列為候選，不升級成長期偏好。
- 一條規則在實務上沒起效時就改，並寫明它靠什麼生效：始終在 Context 裡、在載入路徑上，還是由腳本檢查。

## 新增、移動、刪除主題

- 更新主題索引；在觸發表加一行（根路由不加）；確認沒有未被索引的主題，也沒有指向舊路徑的引用。

## 完成前核對

`scripts/check_instructions.py` 做機械部分，人工仍逐條核對：

1. 預期的 `AGENTS.md` 都存在。
2. 每個主題都被索引。
3. 路由引用的主題都存在。
4. 每個主題至少被一個路由引用。
5. 讀者索引不連結 `AGENTS.md` 或 `.agents/`。
6. 路由保持簡短，沒有形成第二份規範副本。
7. 根路由只有指標。
